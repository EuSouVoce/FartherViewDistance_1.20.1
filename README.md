## Since v10.0.0 **it now**:
*  Uses: Java 21
* Every version will be compiled against a paper version, if you are seeking retro-compatibility, use an older version,
* If the server is running in an incompatible version it will disable the plugin and log this info.

## Runtime branch selection (ServiceLoader)

The core plugin now resolves `code.branch` dynamically at startup using Java `ServiceLoader`.

- It selects the **newest compatible** branch provider for the current server Minecraft version.
- The built-in provider currently covers `1.21.10` to `1.21.11`.
- New branch implementations can be shipped as external jars exposing
    `xuan.cat.fartherviewdistance.code.branch.BranchProvider` in `META-INF/services`.

This enables keeping one stable core while adding/updating NMS branches independently.

### Bootstrap auto-download (Paper PluginLoader)

The plugin now also uses a Paper `PluginLoader` (`BranchPluginLoader`) to try loading an external branch module automatically before plugin enable.

- Default Maven repo: `https://maven.pkg.github.com/EuSouVoce/FartherViewDistance_1.20.1`
- Default coordinates pattern:
    - group: `xuan.cat.fartherviewdistance`
    - artifact: `fartherviewdistance-branch-<minecraftVersion>`
    - version: highest available from `maven-metadata.xml`

Configure bootstrap in `plugins/FartherViewDistance/config.yml` under `branch-autoload`.

- `branch-autoload.enable: false` disables bootstrap autoload
- `branch-autoload.minecraft-version: "1.21.11"` forces minecraft version for resolution
- `branch-autoload.repository-url` configures the Maven repository (by default is the github one.)
- `branch-autoload.repository-user` and `repository-token` configure private repositories
- `branch-autoload.group-id` and `artifact-prefix` configure Maven coordinates
- `branch-autoload.library-directory` configures the downloaded branch jar cache
- `branch-autoload.offline: true` uses the cached branch version only
- `branch-autoload.cache.enable: false` disables metadata caching
- `branch-autoload.cache.ttl-seconds: 21600` throttles metadata refreshes (default: 6 hours)
- `branch-autoload.cache.force-refresh: true` forces one metadata refresh on startup

The metadata cache lives in `plugins/FartherViewDistance/branch-cache` by default. Downloaded branch jars live in `plugins/FartherViewDistance/branch-libraries`. If GitHub Packages or the network is down, the loader keeps using the last known working branch version from that cache. Failed lookups are recorded for diagnostics, but the loader retries misses so a newly published branch can be picked up on the next restart. For secrets, environment variables `FVD_BRANCH_REPO_USER` / `FVD_BRANCH_REPO_TOKEN` or `GITHUB_ACTOR` / `GITHUB_TOKEN` are also supported.

External branch artifacts are generated by the root `build.gradle` from the configured branch module list. There is no separate template project in this repository.

To add a new generated branch artifact, add a new entry to `branchModules` in `build.gradle` with the target Minecraft version, required compile classpath, artifact version, generated package, and generated provider class name.

Release checklist for a new PaperMC version:

- [docs/NEW-PAPER-VERSION-AUTOLOAD.md](docs/NEW-PAPER-VERSION-AUTOLOAD.md)

Useful branch module tasks:

- `./gradlew.bat clean jar` builds the core jar and all generated branch jars across the configured Minecraft build variants
- `./gradlew.bat branchJars` builds generated branch jars across the configured Minecraft build variants
- `./gradlew.bat publishBranchModulesToLocal` writes those artifacts to `build/branch-repo`
- `./gradlew.bat publishBranchModulesToGitHub` publishes those artifacts to GitHub Packages, skipping an artifact when the same version already exists
- Add `-Pbranch.publish.force=true` to publish tasks to force publishing an already existing branch version
- To publish to another Maven repository with credentials from `~/.m2/settings.xml`, use `-PmavenServerId=<server-id>` together with `-Pgpr.repoUrl=<repo-url>`
- Example (ImperioGames): `./gradlew.bat publishBranchModulesToGitHub -Pgpr.repoUrl=https://repo.imperio.games/public/ -PmavenServerId=imperiogames -Pbranch.publish.force=true`

The aggregate branch tasks run one isolated Gradle build per required Minecraft/Paper classpath. This keeps `26.x` branches on Java 25 / `26.x.build.+` while `1.21.x` branches keep the normal Java 21 classpath.


### If you wish to build it yourself:

1. run `./gradlew build`
2. Add the resulting jar from `build/libs` to your plugins folder and be happy.
